Fine-Tune It:
Instructor Guide

How to run the fine-tuning workshop in your class.

Before class Versions Assignment If something breaks Student guide

Students fine-tune a small open language model (Qwen2.5-0.5B, LoRA) on one Vista GPU to sort real CFPB consumer complaints into six categories. They score it before (about 17%, chance) and after (about 73% in the dry run), then test it on complaints they write.

Everything runs from notebooks/01-fine-tune.ipynb. Slides are shared separately by Dr. Scruse (Google Slides); one deck per version.

Before class

01

Reservation

Dr. Scruse submits a Vista reservation for each class date. Students enter allocation TRA25001 and that class's reservation name in the portal.

The student page and screenshots show reservation HCSC106 (from the CSC 106 run). Tell students the reservation name for their class.
02

Shared environment

The notebook points SHARED at:

/work/10539/ashleyscruse/vista/inspire-shared

It holds the data, model, and Python, and it is already built. To rebuild elsewhere, run scripts/setup_shared.sh from a GPU compute-node session (see the README).

03

Student logins

Every student logs in to the portal, finishes MFA, and connects their account to Vista before class.

Pre-work, graded: a screenshot of their account at accounts.tacc.utexas.edu showing they can log in and that MFA uses an authenticator app (Okta Verify or Google Authenticator). Never SMS.

In CSC 106 the first part of class went to logins. With logins done ahead, the notebook fits in 50 minutes.

04

Run-through

Run the notebook once from a student-like account and time Step 3 (training). Training on 6,000 examples took about 27 seconds on one GPU.

A

Intro CS (CSC 106)

75 minutes. Deck: intro-cs-fine-tune.pptx

Focus: how supercomputers train AI and what fine-tuning is.

Run: Steps 0 to 5.

Close: what changed between before and after.

B

Computer Ethics

50 minutes. Deck: ethics-fine-tune.pptx

Focus: the ethics of fine-tuning: where the data came from and consent, who gets misclassified, who is accountable.

Run: Steps 0 to 5. Skip Step 6. In Step 5, students try to break the model: vague complaints, two problems at once, slang.

Close: three discussion questions.

  • What broke it?
  • Who should check?
  • Would you deploy it?
C

Software Engineering and Advanced Software Engineering

About 2.5 hours. Deck: swe-fine-tune.pptx

Focus: how fine-tuned models benefit software: where a model fits in an app, a fine-tuned small model vs a big chat API, and shipping it (tests, versioning the adapter, drift).

Run: Steps 0 to 6. In Step 6 each student changes one setting (more data, shorter input, or more passes) and compares results like an A/B test.

Close:

  • What would you build?
  • What did your experiment show?
  • When would you skip it?
NOTE  Session 2 (notebooks/02-make-it-faster.ipynb, multi-node scaling) needs 4 GPU nodes per team and is not part of these class versions.

Assignment

Students run every cell, then download their completed notebook (01-fine-tune.ipynb, with all outputs) and submit it. In Jupyter's file browser, right-click the notebook and choose Download.
